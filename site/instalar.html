Instalação

Colocar o Tainá no ar.

Este guia assume que você não é técnico: nunca abriu um terminal, ou abriu mas nunca instalou nada. Do começo ao fim, sem ajuda de ninguém, em menos de 30 minutos.

Cada termo técnico deste guia está explicado em uma linha no glossário. Travou numa palavra? Volte lá.

Você pode usar um Raspberry Pi, um mini PC ou uma VPS. Os comandos são os mesmos nos três: o Docker baixa automaticamente a imagem certa para a máquina. Não há CLI para instalar nem arquitetura para escolher.

Se você só quer experimentar numa caixa local, pare depois de criar a comunidade. Domínio, acesso remoto e disco de backup são para quando a comunidade for usar de verdade.

Instale o Docker

O Tainá roda dentro do Docker, e o Docker Compose cuida de iniciar e atualizar o serviço. No Linux e no Raspberry Pi OS, cole o bloco abaixo e aperte Enter:

Terminal 
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"

Saia da sessão e entre de novo para a permissão do Docker valer. Depois confira docker info e docker compose version. Se os dois comandos responderem sem erro, está pronto.

Baixe o pacote do Tainá

O pacote do Tainá traz a configuração pronta. Você não precisa compilar o aplicativo nem instalar uma CLI. No terminal, rode:

Terminal 
curl -fsSL https://github.com/taina-labs/taina/archive/refs/heads/main.tar.gz | tar -xz
cd taina-main/deploy/compose
./taina init

O último comando cria o arquivo taina.conf e a pasta backups. Rode os próximos comandos dentro dessa pasta taina-main/deploy/compose.

Configure o primeiro acesso

Abra a configuração com nano taina.conf. Para criar a comunidade no navegador da própria máquina, ou por um túnel SSH, deixe estas três linhas assim:

taina.conf 
url_scheme = http
hostname = 127.0.0.1
url_port = 4000

Não mude as outras linhas. No Nano, salve com Ctrl+O, aperte Enter e saia com Ctrl+X. O segredo das sessões é criado e guardado automaticamente no primeiro boot; ele não fica no taina.conf.

Suba o Tainá

O Compose baixa a imagem publicada, inicia o Tainá e espera o aplicativo responder que está saudável:

Terminal 
docker compose up --detach --wait
docker compose ps

Quando o serviço taina aparecer como saudável, ele está pronto para o primeiro acesso. Por segurança, a porta fica disponível apenas na própria máquina.

Crie a comunidade

Abra http://127.0.0.1:4000/setup no navegador da máquina. Se ela não tiver navegador, abra um terminal no seu computador e crie um túnel SSH, trocando o usuário e o endereço pelos da sua máquina:

Terminal do seu computador 
ssh -L 4000:127.0.0.1:4000 usuario@servidor

Deixe esse terminal aberto e use o mesmo endereço acima no seu navegador. Vão aparecer três telas:

  • Nome da comunidade. Cada instância é uma comunidade só, e o nome é definitivo para sempre.
  • Quem cuida da máquina. Um nome de usuário, um nome de exibição e uma senha. Essa pessoa é a zeladora, não administradora.
  • Armazenamento. O Tainá mostra onde os arquivos vão ficar e quanto espaço livre existe.

Depois do último passo você entra logado. A comunidade foi criada e você é a primeira pessoa dela.

Convide a primeira pessoa

No menu, abra Membros e depois Convidar. O Tainá mostra um link de convite e um QR code. A pessoa abre e cria a conta dela. Não existe e-mail no Tainá, e isso é uma decisão: menos uma senha guardada em servidor de terceiro.

Acesse de fora com Tailscale

Para um acesso privado, sem abrir portas no roteador, o caminho mais simples é o Tailscale. Instale-o na caixa e nos aparelhos de quem vai acessar, entre na mesma conta e rode na caixa:

Terminal 
tailscale serve --bg 4000
tailscale serve status

O segundo comando mostra o endereço HTTPS. No taina.conf, use esse nome em hostname, mude url_scheme para https e url_port para 443. Depois rode docker compose restart taina para os novos convites usarem esse endereço.

Ou publique com Caddy e um domínio

Se a comunidade tem um domínio e a caixa pode receber conexões da internet, o Caddy faz o proxy para o Tainá e emite o certificado HTTPS automaticamente. Antes de começar, aponte os registros A e AAAA do domínio para o IP da caixa e libere as portas 80 e 443 no firewall. Numa máquina em casa, também encaminhe essas duas portas no roteador. A porta 4000 continua fechada para a internet.

No Debian, Ubuntu ou Raspberry Pi OS, instale o Caddy:

Terminal 
sudo apt update
sudo apt install -y caddy
sudo nano /etc/caddy/Caddyfile

Substitua o conteúdo do arquivo pelo bloco abaixo, trocando o endereço pelo domínio da comunidade:

/etc/caddy/Caddyfile 
nuvem.suacomunidade.org {
    reverse_proxy 127.0.0.1:4000
}

Salve o arquivo e ative a configuração:

Terminal 
sudo caddy fmt --overwrite /etc/caddy/Caddyfile
sudo systemctl reload caddy

Por fim, no taina.conf, configure o mesmo domínio e reinicie o Tainá:

taina.conf 
url_scheme = https
hostname = nuvem.suacomunidade.org
url_port = 443
Terminal 
docker compose restart taina

Acesse https://nuvem.suacomunidade.org. O Caddy renova o certificado sozinho. Se o HTTPS não abrir, confira o DNS, as portas 80 e 443 e os logs com sudo journalctl -u caddy.

Confira o backup

A configuração do Oka já vem com backup_enabled = true. Os arquivos ficam na pasta backups, ao lado do compose.yaml. Para criar um backup agora, rode:

Terminal 
./taina backup

Copie os arquivos dessa pasta para um disco externo ou outro lugar fora da caixa. E ensaie a restauração: um backup que nunca foi testado não é backup.

Para atualizar depois, faça um backup e use o Compose para baixar a imagem nova e recriar o serviço. As migrações de banco rodam sozinhas no boot.

Atualização 
./taina backup
docker compose pull
docker compose up --detach --wait
